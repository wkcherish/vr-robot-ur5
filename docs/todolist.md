## 五、补充提醒

- 当前代码中最容易“看起来像完成了、其实没完成”的部分，是 `execute_task` 和 `control.vue` 的工具操作区，它们现在更多还是演示入口，不是真正任务系统。
- 当前最不建议的路线，是在末端 D405、`RGB-D` 数据格式、Quest3 录制链和脚本化任务都没稳定前，直接开始 RL。
- 当前最需要文档里反复强调的顺序，是“先 D405 -> 再 `RGB-D` 数据格式 -> 再 Quest3 人工采集 -> 初训模型入库 -> 可选 MuJoCo 验证 -> RL 微调 -> RL 模型入库 -> 可选 MuJoCo 再验证 -> 预留实机部署入口”。
- 当前最值得保留的资产，是主分支已经存在的前后端同步链路和 MuJoCo viewer 桥接逻辑，后续 Quest3 输入桥接可以尽量复用这套思路。
